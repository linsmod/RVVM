## 1. 目标与威胁模型

把 guest 当成**不可信的用户态程序**，而不是宿主的管理员：

- 宿主能做的事，不能因为「guest 里是 root」就自动变成 guest 的默认能力。
- 特权能力（访问宿主目录、控制 supervisor/其他实例）必须由**宿主显式授予**，
  默认关闭。
- 纯信息泄漏（宿主路径、pid、磁盘、inode、uptime、构建路径）能合成/裁剪的，
  不把宿主原值直接交给 guest。
- 改动面很大、需要工具链或架构级调整的，登记 `issues/`，不在本批硬塞。

## 2. 已确认的暴露点

### P0：隔离边界实际不存在

1. **guest 可 `mount -t hostfs` 任意宿主目录，读写**
   - 实测 `mount -t hostfs 'C:\' /mnt/c` 能看到 `Program Files` 等；
     临时目录写入在宿主真实落盘。
   - 代码：`src/core/rvvm_user.c` 的 `rvvm_user_mount()` 把 guest 给的 source
     当宿主路径；`rvvm_user_mount_hostfs()` 是宿主预挂载，二者共用 `mount_row_add()`。
2. **guest 能访问 supervisor API（默认无 token）**
   - 实测 guest 内 `wget http://127.0.0.1:7911/api/health` 返回
     `release`、`rootfs`、`log_path`、`pid`、`endpoint` 等绝对路径/宿主 pid；
     还能看到其他实例。
   - 原因：guest 的 socket 就是宿主 socket，`client_address == 127.0.0.1`；
     `supervisor.py` 在 token 为空时信任 loopback。
   - POST/DELETE 同一鉴权分支，可 stop/delete/exec 其他实例（未实际发破坏性请求）。
3. **`/run/vpsessiond` 是所有实例共享的可写宿主目录**
   - guest 能看到 `auth.pub`、所有 `<port>.ready`、混写的 `vpshhd.log`/
     `tinysshd.log`；能创建/删除/覆盖这些文件。
   - 实测 guest 写文件后宿主 `runtime/run` 立即出现。

### P1：guest 可见的宿主元数据

4. **`/rootfs.modes`**：per-instance mode store 放在 `<rootfs>/rootfs.modes`，
   文件内容是 `mode\tH:\...` 宿主绝对路径；guest 通过 hostfs chmod 时也会把
   宿主路径写进去。
5. **`/.ash.lock`**：per-instance lock 放在 `<rootfs>/.ash.lock`，内容
   `pid=<宿主 core pid>`；guest 可读、可删、可改。
6. **`df`/`statfs`**：rootfs 行落回宿主 `statfs()`，`df -h /` 显示宿主卷
   1000G/972.8G/97%，`df -i` 显示宿主 inode 数。
7. **`st_dev`/`st_ino`**：普通宿主持久文件的 `st_dev`/`st_ino` 直接来自宿主；
   `st_ino` 与 NTFS file ID 一致（`fsutil file queryfileid` 实测相等）。
   `getdents64` 的 `d_ino` 也来自宿主。
8. **uptime**：`/proc/uptime`、`sysinfo.uptime`、`/proc/<pid>/stat` starttime、
   guest `CLOCK_MONOTONIC` 都是宿主 uptime（实测与宿主 `LastBootUpTime` 一致）；
   `/proc/stat` 的 `btime` 目前是 `time(NULL)`，语义错误。
9. **随包 guest 二进制**：`/data/app/*/bin/*.exe` 和 `/sbin/vpshhd` 带
   `H:/github_repos/RVVM`、`h:/github_repos/libriscv`、
   `C:\Users\...\zig...`、完整 DWARF、`clang 21.1.0` 等构建路径。
10. **`uname -a`**：`RVVM v0.7-git-g3fb452d-dirty`，暴露构建 commit/dirty；
    `/proc/mounts` 头写 “Generated by the VirtPass host”。

### 已验证没有泄漏

- hostname/nodename（`localhost` / `rvvm-user`）、`/proc/cmdline`、`/proc/cpuinfo`、
  `/proc/meminfo`、`/proc/loadavg`、`/proc/version`、`/proc/filesystems`、
  `/proc/self/environ`、`/proc/net`、`/sys/class/net`、`/etc/{hosts,hostname,resolv.conf}`。
- `/proc/self/{exe,cwd,root,fd}` 显示 guest 路径。
- supervisor 网页头部只显示 release basename（API JSON 不是）。

## 3. 设计决策（已按推荐项执行）

1. **guest hostfs 默认拒绝**
   - core 新增宿主策略 `rvvm_user_set_guest_hostfs(machine, bool)`，默认 false。
   - guest 指定 source 的 `mount -t hostfs` 在未授权时返回 `-EPERM`。
   - 宿主预挂载 `rvvm_user_mount_hostfs()` 不受影响。
   - `rvvm_ash` 新增 `--allow-guest-hostfs`，只给测试/高级用法显式打开；
     `rvvm_winhost` 默认关闭。
2. **supervisor 永远需要 token**
   - 无 `--token`/`SUPERVISOR_TOKEN` 时自动生成，写入
     `<release>/runtime/supervisor/token`（尽量 0600），启动只打印路径。
   - HTTP API 与 WebSocket 都要求 token，loopback 不再免鉴权。
   - `probe_daemon()` 收到 401 仍算「有 daemon 在」，提示 token required。
   - API 不再返回绝对 `release`/`rootfs`/`log_path`/`endpoint`；`note` 不拼全路径。
   - `us.py` 读取 `--token`/`US_TOKEN`/`SUPERVISOR_TOKEN`，再回退到
     `runtime/supervisor/token`；`ws_smoke.py` 支持 token。
3. **每实例独立 `/run/vpsessiond`**
   - supervisor 建 `runtime/run/<port>/`，把 `auth.pub`、`<port>.ready`、日志放进去。
   - core/ash 新增 `--run-dir`，`win32_cmdpost_bridge` 把它挂到 `/run/vpsessiond`。
   - `us rm` 删除该目录；`stop` 保留（重启复用）。
4. **mode store / lock 移出 guest root**
   - per-instance：`<rootfs>.modes`、`<rootfs>.lock`（rootfs 同级）；
   - default（无 `--rootfs`）保持 `runtime/rootfs.modes`、`runtime/ash-core.lock`；
   - 不持久化 prefix 之外的 chmod（hostfs 路径），避免把宿主路径写进 mode store；
   - `us rm` 删除 rootfs 时一并删除 sidecar。
5. **合成 guest 元数据**
   - `statfs`：rootfs/hostfs 行合成固定大小/inode，不落回宿主；
   - `st_dev` 固定、`st_ino = hash(host dev, host ino)`，`getdents64` 同步，`statx` 同步；
   - uptime/monotonic 以 run 起点为 0；`btime` 用 guest boot epoch。
6. **构建信息**
   - `uname` 去掉 commit/dirty；`/proc/mounts` 头改成中性文字；
   - guest app 加 `-ffile-prefix-map`/`-fdebug-prefix-map`，release 链接加 `-s`/strip；
   - 如果 zig 预编译 libc 的路径无法 remap，release 只做 strip，debug 保留，登记 issue。

### C4 恢复点（2026-11-19 已跑）

  `rvvm_user.c` `mode_path_persistable()`（prefix 内才持久化）与 `path_has_prefix()`
  接受 `\\`；`supervisor.py` `rm` 删除两个 sidecar；`selftest.py` 增 9 项。
- 验证：
  1. guest `/` 无 `rootfs.modes`、`.ash.lock`；
  2. 宿主 `<rootfs>.modes`/`<rootfs>.lock` 存在（lock 内容仍是宿主 pid，但不在 guest 可见）；

  guest 不可见；hostfs 路径不写入。旧实例（旧二进制）内的 `rootfs.modes` 需要 `us rm`
  或重启到新二进制后才消失。
